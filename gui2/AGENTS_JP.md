# GUI2 開発ガイド

## 設計目標

GUI2 は LVGL ベースの TWRP 次世代タッチインターフェースです。現代のスマートフォンに適したレスポンシブレイアウト、滑らかなタッチ操作、拡張可能な recovery ページフレームワークの提供を目指します。

主な目標：

- さまざまな解像度、画面方向、画面密度に対応する。
- マルチタッチ入力をサポートし、将来のピンチズームなどのジェスチャーに備える。
- スクロール、アニメーション、シャドウ、グラデーションなどの視覚効果を維持する。
- TinyTTF によるフォントの動的描画を使用し、中国語（簡体字・繁体字）および英語、異なる文字サイズをサポートする。
- ステータスバー、ページ上部バー、コンテンツ領域、下部ナビゲーションを再利用可能な共通フレームワークとして統一する。
- 既存の TWRP recovery 機能と段階的に統合し、旧 GUI を一度に破壊しない。

## 設計方針

- **フレームワークとコンテンツの分離**：固定システム領域は GUI2 shell が管理し、各ページはコンテンツの作成のみを担当する。
- **レスポンシブ設計を優先**：サイズ、余白、フォントは framebuffer の短辺（大画面ではパネルの物理サイズ）に応じて動的に計算し、特定の端末向けに座標を固定しない。
- **タッチ操作を優先**：操作領域はコントロール全体を覆うこと。押下後にコントロールの外へ移動してから離した場合は、クリックをキャンセルしたものとして扱う。
- **コンポーネントの再利用**：カード、ナビゲーションボタン、ページタイトル、スクロールコンテナ、言語オプションは共通の生成関数で作成する。
- **リソースの実行時読み込み**：テーマフォントなどのリソースは `/twres` から読み込み、端末固有のリソースをページロジックにハードコードしない。

## 開発ロードマップ

1. LVGL の framebuffer 表示、タッチ入力、マルチタッチ入力、パフォーマンス制御を完成させる。
2. 統一 GUI2 shell を構築する：固定ステータスバー、ページ上部バー、スクロール可能なコンテンツ領域、下部ナビゲーションバー。
3. ページとコンポーネントのモデルを構築し、インストール、消去、バックアップ、復元、マウント、高度な機能、設定などのページを段階的に実装する。
4. i18n、フォント、テーマ、端末のセーフエリアへの対応を完成させる。
5. 既存の recovery 操作機能を GUI2 のページに接続する。
6. GUI2 を recovery のデフォルトメイン画面としつつ、同一プロセス内での互換性フォールバックとして旧 GUI も維持する。

## 現在の進捗

完了済み：

- LVGL と TWRP minui framebuffer の表示経路。
- 低遅延タッチ入力、スクロール、マルチタッチ入力の基礎。
- NEON によるカラー変換の最適化。
- スマートフォン向けレスポンシブレイアウトと動的サイズ計算。
- 固定ステータスバー、ページ上部バー、コンテンツスクロール領域、下部ナビゲーションバー。
- フローティング式下部ナビゲーション：ナビゲーションは、左側に独立した円形の戻るボタン、右側に3ボタン一体型のカプセルを配置する `1+3` 構造とする。2つの外形の背景、半円形の角丸、枠線、シャドウは shell が一元的に描画する。カプセル内部のボタンは操作とアイコンのみを提供し、それぞれが独自に角丸背景を描画してはならない。
- ページコンテンツはフローティングナビゲーションの下まで連続して配置し、shell が局所的な透明黒グラデーションマスクを提供する。マスクはスクロールコンテンツの上、ナビゲーションコントロールの下に配置し、border、outline、shadow を付けてはならない。
- 戻る、ホーム、ページルーティングのロジック。
- ページの PUSH/POP/REPLACE 遷移アニメーション：前進時は新しいページが右側から入り、戻る時は新しいページが左側から入る。アニメーション中はページコンテンツへの入力を一時的に無効化し、固定ステータスバーと下部ナビゲーションは動かさない。
- ホーム画面の機能カード、汎用操作用のプレースホルダーページ、および設定、言語、タイムゾーン、ハードウェアの各ページ。
- 再起動ページ：下部バーの Power ボタンから開く。System、Power Off、Recovery、Fastbootd、Bootloader、Download、EDL に対応し、各項目はビルドパラメーターに応じて表示する。タップ後は矢印付きスライダーで確定する。
- 再起動ページの A/B スロット領域：ビルド時に `AB_OTA_UPDATER` が有効で、実行時に有効な `A/B` アクティブスロットが存在する場合のみ表示する。スロット切り替えには recovery の boot control ロジックを再利用する。
- 英語、簡体字中国語、繁体字中国語の i18n。
- TinyTTF による動的フォントサイズと中国語フォントの描画。
- `libgui2` 静的ライブラリと公開エントリーポイント `gui2_start()`。
- `gui2/backend/` における LVGL から独立した設定ストレージおよび状態取得インターフェース。
- recovery DataManager アダプター：永続設定には引き続き `.twrp_settings` を使用する。
- 実時刻、バッテリー残量、充電状態、12/24 時間表示。
- 時刻／タイムゾーン設定（タイムゾーン、UTC オフセット、DST）と、言語設定の永続化。
- 画面機能 backend：旧 GUI と互換性のある PNG スクリーンショット、自動／手動の画面消灯、タッチによる画面復帰。
- 音声なしの VP8/WebM 内蔵画面録画：15/24/30/45/60 FPS、有界のフレームドロップキュー、バックグラウンドエンコードに対応し、Android メディアサービスに依存しない。
- shell レベルのステータスバー・プルダウン式クイックメニュー：スクリーンショット、画面消灯、録画の開始／停止。録画状態はステータスバーにも同期表示する。
- recovery のデフォルト GUI2 起動、初期化失敗時のフォールバック、実行中の旧 GUI への切り替え。
- GUI2 の第1段階のモジュール化リファクタリングを完了。エントリーポイント `gui2.cpp` は recovery のビジネスコールバックと組み立てを担当し、`app/` はライフサイクル／メインループ、`shell/` は永続的なシステム層、`pages/` はページ、`components/` は再利用可能なコントロール、`core/` は汎用 UI 基盤、`theme/` はフォントリソース、`backend/` は recovery/system の機能を管理する。
- 再起動機能は `backend/reboot_backend` 経由で GUI2 に注入済み。確定後、旧 GUI が使用する再起動状態を書き込み、GUI2 を終了する。その後の最終同期、アンマウント、再起動は `twrp.cpp` が一元的に実行する。

現在の制約：

- 起動前に既存の復号化や読み取り専用確認など、recovery の既存の前処理ページをサポートするため、旧 GUI を短時間初期化する必要がある。その後、旧 GUI のリソースを解放してから GUI2 に移行する。
- 再起動と A/B スロット切り替えは統合済みだが、インストール、消去、バックアップ、復元、マウント、高度なツールなどの実際の recovery 操作は、GUI2 のページにまだすべて統合されているわけではない。

## 注意事項

### ソースコードとビルド

- `gui2/AGENTS.md` は `bootable/recovery` Git ワークツリー内にある。`git status`、`git diff --check` などのバージョン管理チェックは、このディレクトリで実行する。Android ビルドシステムのソースルートはその2階層上にあるため、`source build/envsetup.sh`、`lunch`、`m/mka` はソースルートから実行する。
- 現在の実機検証ターゲットは `sm8850`：

  ```bash
  source build/envsetup.sh
  lunch twrp_sm8850
  mka installclean
  mka recoveryimage
  ```

- 最終的な `recoveryimage` を生成する前には、毎回必ず `mka installclean` を実行する。モジュール単体の増分ビルドによる検証では、必要に応じて対象モジュールのビルドを使用してよい。
- 直近の検証コマンドと結果：

  ```bash
  git diff --check                         # 成功（bootable/recovery で実行）
  source build/envsetup.sh
  lunch twrp_sm8850
  m libgui2                                # 成功
  m recovery                               # 成功
  mka installclean
  mka recoveryimage                        # 成功。out/target/product/sm8850/recovery.img を生成
  ```

  recovery 全体のビルドで表示される `depmod` のモジュールメタデータ不足は、既存の端末ビルドに関する警告であり、GUI2 のコンパイルエラーではない。

### アーキテクチャとリソース

- GUI2 のソースコードは、次の責務に従って構成する：

  ```text
  app/        GUI2 のライフサイクル、メインループ、ランタイムサービス、遅延画面操作
  core/       metrics、スケーリング、クリックキャンセル guard、スクロール慣性などのビジネスロジックに依存しない基盤
  shell/      ステータスバー、page host、上部バー／スクロール用フレームワーク、下部バー、クイックパネル、システムポップアップ
  pages/      page router、ページ builder、ページ状態、ページ固有ロジック、再起動ページ
  components/ 再利用可能な LVGL コントロールとカード
  theme/      TinyTTF フォントのライフサイクル
  backend/    recovery/system backend（設定、ハードウェア、画面、再起動）。LVGL に依存しない
  ```

- GUI フレームワークを変更する場合は、`create_gui_shell_base()`、`page_host::build()`、共通コンポーネントを優先的に使用する。各ページが固定ステータスバー、上部バー、下部ナビゲーション、クイックパネル、システムフィードバック層を直接管理してはならない。
- `gui2_start()` は、注入された recovery services の検証、`app/gui2_lifecycle` によるグラフィックリソースの初期化、Shell の組み立て、ステータスバー controller の起動、`app/gui2_loop` の開始のみを担当する。新しい LVGL メインループやリソース解放ロジックをエントリーポイントに戻してはならない。再起動 service も context 経由で注入すること。
- `app/gui2_lifecycle` が TinyTTF、LVGL、display、input、SVG cache の初期化／解放順序を一元管理する。初期化に失敗した場合は、同じクリーンアップ経路を再利用する。
- `app/gui2_loop` が LVGL timer、screen tick、入力 activity、キー、スクロール、present、パフォーマンス timeout を一元的に処理する。ページコールバックが受け取るのは抽象化されたアクションのみとする。
- `page_router` はページ遷移の唯一の入口であり、ページ間の戻る操作に使用する現在のページ request を保持する。新しいページを追加する場合は、`page_id`、builder/payload、ルーティング、戻る動作、i18n を登録する。ページ間で `show_*` を直接呼び出してはならない。
- `page_host` は現在のページレイヤーと scaffold を所有する。ページ builder が受け取るのは、options 内の content、metrics、strings、ビジネスコールバックのみとし、Shell の永続オブジェクトを作成してはならない。
- `gui2/core/ui_metrics` の `ui_metrics`、`ui_px()`、`card_inner_padding()`、`single_line_card_height()`、`navigation_safe_area()` はグローバルなサイズ API である。新しいモジュールでサイズ計算方針を複製してはならない。
- `gui2/core/ui_event_guard` は、タッチキャンセルとクリック時の振動を一元的に実装する。新しいクリック可能オブジェクトは `add_press_cancel_guard()` を再利用し、独自のクリックキャンセル状態を実装してはならない。
- `shell/` の controller は、それぞれが LVGL オブジェクトと timer を保持する。ステータスバーは `status_bar_controller`、クイックパネルは `quick_panel_controller`、システムフィードバックは `screen_feedback`、画面操作は `app/screen_actions` を使用する。停止／終了時には、所有者が自身の timer、スレッド、オブジェクト参照を解放すること。
- 下部ナビゲーションは shell レベルの永続コンポーネントである。すべてのページは同じナビゲーションインスタンスと `page_host`／scaffold のライフサイクルを再利用する。ページが下部ナビゲーションを作成、置換、複製したり、ページ固有の座標でナビゲーションを模倣したりしてはならない。
- フローティングナビゲーションの視覚的な重なり順は、スクロールページコンテンツ → 局所グラデーションマスク → ナビゲーションコントロールに固定する。ナビゲーション背景自体は透明に保ち、ページコンテンツがその下まで延びるようにする。グラデーションマスクはナビゲーション上端の少し上の遷移領域と、ナビゲーション下部の領域のみを覆い、目に見える矩形の枠を形成してはならない。
- ナビゲーションの外形には、明示的な半高の角丸（コントロール高さの半分）を使用する。テーマ既定の `LV_RADIUS_CIRCLE` のみに依存してはならない。右側の3ボタンは親カプセルが一元的に枠線を描画し、子ボタンは背景を透明、角丸をゼロ、枠線をゼロに設定する。
- 自作の再利用可能な LVGL コンポーネントは `gui2/components/` に統一して配置する。現在のコンポーネントには icon、choice card、setting card、slider card、swipe slider、quick action button、section label、apply button がある。操作コンポーネントは、状態、描画、ヒットテスト、イベントを1つのカスタム widget で処理すること。視覚レイヤーの上に透明な標準コントロールを重ねてはならない。ページはコンポーネントの組み合わせとビジネスイベントのバインドのみを担当する。`swipe_slider` は常に矢印を描画し、削除済み LVGL オブジェクトへの参照を解放する `detach()` を提供する。
- ページタイトルには常に `ui.brand_font` を使用する。タイトルのフォントサイズを変更する場合は、ホーム画面、2階層目、3階層目のページを同時に確認する。
- GUI2 は `/twres` 内の実行時フォントリソースと backend を使用し、特定端末向けに解像度、角丸セーフエリア、フォントサイズをハードコードしない。
- グローバルなサイズ計算には `gui2_core::ui_metrics::scale` と `gui2_core::ui_px()` を統一して使用する。スマートフォンのスケーリング基準は短辺 1200px とする。最小／最大倍率は保護目的に限り、高解像度レイアウトに未スケーリングの固定上限を設けてはならない。新しい shell、カード、コンポーネントのサイズは、このスケーリングに組み込むこと。
- 大画面（`gr_fb_physical_size()` が報告するパネル短辺が 100 mm 以上。タブレット、折りたたみ端末の内側画面）は物理密度に基づいてスケーリングし、`ui.large_screen` を true にする。パネルサイズが不明な場合は、常にスマートフォンとして扱う。大画面のコンテンツ領域は幅を制限して中央配置する。横方向の位置決めには `ui.content_left` を使用し、`outer_margin` は間隔としてのみ使用する。カードリストコンテナでは `set_card_grid()` を呼び出し、カード幅には `card_width_in(parent)` を使用する。同じ行のカードの高さは `page_host::settle()` が一元的に揃える。スマートフォンの横向き表示に特別な対応は行わない。
- GUI2 は旧 GUI のテーマインポート、`ui.xml` によるカスタムテーマ、テーマの再読み込みをサポートしない。これらのロジックは引き続き旧 GUI が独立して管理する。
- `gui2/` 内のソースファイルにはライセンスヘッダーを追加しない。ビルドシステム内のモジュールライセンス宣言は Android.bp の規約に従って維持する。

### ページと操作

- 新しいページは必ず `pages/page_router`、戻る動作、i18n、スクロール領域、下部ナビゲーション、タッチキャンセルロジックに接続する。ページ builder は `pages/` に配置し、`gui2.cpp` に `show_*` の実装を追加し続けてはならない。
- 新規／変更ページは `page_host` と共通スクロール scaffold を通じてフローティングナビゲーションのロジックを再利用する。`main_content` の表示高さは画面下端まで延ばすこと。ナビゲーションのために `height - nav_height` でスクロールビューポートを短くしてはならない。
- すべてのスクロール可能ページでは、コンテンツ末尾にナビゲーションセーフエリアを確保する。少なくとも `navigation_safe_area()`（ナビゲーションの高さと外側余白）を含めること。このセーフエリアはスクロールコンテンツの bottom padding または末尾のスペーサーとして設け、最後の項目をフローティングナビゲーションの上まで完全にスクロールできるようにする。ページに固定の「適用」などの操作ボタンがある場合は、ボタン自体の高さと間隔も追加で確保する。
- ページ下部のグラデーションは shell が一元的に作成・再利用する。各ページでグラデーションレイヤーを重複作成してはならない。グラデーションレイヤーは装飾専用オブジェクトとし、border、outline、shadow、クリック、スクロール属性を無効にし、透明から半透明の黒への局所グラデーションで暗くする。
- クリック可能な子コントロールを追加する場合は `LV_OBJ_FLAG_CLICKABLE` を確認する。装飾用の子オブジェクトが親カードのイベントを横取りしてはならない。すべてのクリック可能なコントロールは、押下後に領域外へ移動してから離した場合にクリックがキャンセルされるようにする。
- `lv_obj_create()` はデフォルトでスクロール属性を持つ場合がある。`main_content` など明示的にコンテンツをスクロールする領域を除き、カード、ボタン、ポップアップ、レイアウトコンテナでは `disable_scrolling()` を呼び出し、スクロールバーも無効にする。
- ページは options/context を通じてのみ `metrics`、言語パッケージ、content、ビジネスコールバックを受け取る。`sysfs`、minui、グローバル DataManager、recorder に直接アクセスしてはならない。
- ページ状態（選択項目、slider binding、LVGL card 参照）は、対応する page state/controller にまとめる。エントリーポイントに散在する static 状態変数を追加し続けてはならない。
- 再起動ページが受け取るのは backend が提供する機能、現在のスロット、抽象化されたコールバックのみとする。再起動先カードにはアイコンや説明を付けず、カードの高さは `single_line_card_height()` に統一する。確定スライダーは選択可能な A/B スロット領域の後に配置する。

### レイアウトとコンポーネント

- すべてのカード系コンポーネントは、レスポンシブな水平内側余白として `card_inner_padding()` を再利用する。カード、設定項目、言語項目、タイムゾーン項目、ハードウェア項目、ポップアップ内のカード、情報カードで、それぞれ異なる左右 padding をハードコードしてはならない。カードを調整する場合は、テキスト、アイコン、矢印、複数列の行で利用可能な幅も同時に確認する。
- ナビゲーションアイコンのサイズは、共通の `ui_px()` とナビゲーションボタンのサイズ計算を通じて決定する。スケーリングされない固定ピクセル値を使用してはならない。アイコンを調整する場合は SVG のラスタライズ内容の実際の表示境界も確認し、外側の画像ボックスだけが大きくなって図形が小さいままにならないようにする。
- ページ間の共通化チェックでは、ホーム、操作、再起動、設定、タイムゾーン、言語、ハードウェアの各ページを対象にする。すべてのページで同じフローティングナビゲーションの重なり順、グラデーションマスクの動作、最下部までスクロールした際のセーフエリアを使用すること。ホーム画面だけを個別に調整してはならない。
- 角丸とシャドウを持つカードまたは子カードは、親コンテナの境界から十分な安全距離を確保する。複数列の行では padding を子カードの幅と行の高さに含める。必要に応じて `LV_OBJ_FLAG_OVERFLOW_VISIBLE` を使用し、角丸やシャドウが切り取られないようにする。
- 同じページ内の単一行オプションは `single_line_card_height()` を再利用する。時刻形式、UTC オフセット、タイムゾーンオプション、DST オプション、適用ボタンの高さを統一する。
- 再起動先と A/B スロットのカードは、説明なし・テキスト中央揃えの単一行オプションスタイルを再利用する。確定スライダーには常に矢印を表示し、矢印を非表示にする派生スタイルを設けない。
- ハードウェアスライダーでは、タイトル／数値の行とスライダーを1つのコンテンツグループとして扱い、カード内部でグループ全体を垂直方向に中央揃えする。4方向の余白には統一された `card_inner_padding()` を使用し、グループ内の間隔は個別に制御する。
- スライダーの外観は Miuix スタイルに従う：カプセル形のトラック、コントラストを抑えた背景トラック、青色の塗りつぶし、小さな円形のつまみ。操作用のヒット領域と、見た目上のスライダーサイズは分離する。
- ページタイトル領域のステータスバー下の余白、およびタイトルとサブタイトルの間隔は、shell の共通 metrics で制御する。ホーム画面のタイトルを調整する場合は、すべての2階層目・3階層目のページも同時に確認し、ページごとに座標を固定しない。
- カードのテキスト位置を「タイトル1行＋説明1行」と固定して計算してはならない。テキストグループには実際の幅を設定し、自動折り返しを有効にして、実際の高さに基づいてグループ全体を中央揃えする。必要に応じてカードの高さをコンテンツに合わせて増やす。1行の長いテキストに限り、状況に応じて `LV_LABEL_LONG_SCROLL` を使用する。多数のカードを同時にスクロールさせてはならない。
- ステータスバーのバッテリーアイコン、パーセンテージ、充電アイコンは、それぞれ独立したオブジェクトにする。テキスト更新後に再配置し、順序を「バッテリー、数値、充電マーク」に維持する。動的な幅の変化によって重ならないようにする。

### 設定、ハードウェア、再起動 backend

- すべての永続設定は `backend/settings_store` を通じて扱う。recovery 実装では DataManager を使用し、ページから設定ファイルを直接読み書きしてはならない。
- すべてのハードウェア設定は `backend/hardware_settings` を通じて扱う。ページから sysfs、DataManager、振動 HAL に直接アクセスしてはならない。機能が利用できない場合は入口自体を非表示にし、「利用不可」ページを作成しない。
- すべての再起動操作とスロット操作は `backend/reboot_backend` を通じて行う。ページから DataManager、PartitionManager、TWFunc、minui、sysfs に直接アクセスしてはならない。
- 再起動先の利用可否は、ビルドパラメーターと旧 GUI の仕様の両方に従うこと：`TW_NO_REBOOT_RECOVERY`、`TW_NO_REBOOT_BOOTLOADER`、`TW_INCLUDE_FASTBOOTD`、`PRODUCT_USE_DYNAMIC_PARTITIONS`、`TW_HAS_DOWNLOAD_MODE`、`TW_HAS_EDL_MODE`、`AB_OTA_UPDATER`。利用できない再起動先は非表示にし、「利用不可」カードを作成しない。
- A/B スロットカードは `AB_OTA_UPDATER` だけで判断してはならない。従来の A/B および Virtual A/B 端末との互換性を保つため、実行時に `ro.boot.slot_suffix` が有効な `A` または `B` に対応していることも確認する。
- 再起動の確定時には、旧 GUI が使用する `tw_reboot_arg` と `tw_gui_done` のみを書き込む。GUI2 終了後、`twrp.cpp` の共通再起動フローに処理を引き継ぐ。ページやスライダーから端末の再起動を直接実行してはならない。
- ハードウェアスライダーの値が変化した際には、ハードウェアとメモリの状態をリアルタイムに更新してよいが、`LV_EVENT_VALUE_CHANGED` のたびに `Flush()` を呼び出してはならない。`LV_EVENT_RELEASED` または同等の終了イベントで一括して永続化する。
- 明るさには `tw_brightness`／`tw_brightness_pct` と TWRP の最大値マッピングを使用する。振動には `tw_button_vibrate`、`tw_keyboard_vibrate`、`tw_action_vibrate` を使用し、GUI2 独自の設定キーを追加してはならない。
- タイムゾーンの変更時は、旧 GUI の `Zone[:offset][DSTZone]` ルールに従って `tw_time_zone` を構築し、環境を更新してから `flush()` する。
- 画面録画のフレームレート設定には `tw_screen_record_fps` を統一して使用する。UI で許可する値は 15、24、30、45、60 FPS の5段階のみとする。ページから recorder を直接操作してはならない。
- 録画のフレームレート設定は、ビルド時の `TW_FRAMERATE` を超えてはならない。backend、UI、録画サンプリングで同じ有効上限を使用する。
- 録画フレームレートが変更された場合は backend のメモリ上の設定のみを更新し、スライダーイベントごとに `Flush()` してはならない。スライダーを離したときに一括保存する。

### ライフサイクルと旧 GUI

- GUI2 の display/input/font/LVGL のライフサイクルは `app/gui2_lifecycle` が一元管理する。Shell controller の timer は LVGL の破棄前に停止し、backend worker は owner の `stop()` 内で停止して `join` する。
- スクリーンショット／画面消灯の要求は `app/screen_actions` にキューイングし、このフレームの present 後に実行する。スクリーンショット時の白フラッシュは `shell/screen_feedback` が管理する。ページやクイックボタンから screenshot、screen-off、minui を直接呼び出してはならない。
- GUI2 から旧 GUI に切り替える際、GUI 選択設定を書き込んではならない。終了前にステータススレッドを停止し、LVGL と入力リソースを解放する。GUI2 から旧 GUI への即時切り替えでは、すでに動作している minui/DRM インスタンスを維持し、旧 GUI はリソースと入力のみを再構築する。再度 modeset してはならない。minui を解放するのは GUI2 が完全に終了する場合、または初期化に失敗した場合のみとする。
- 復号化などの前処理ページでは、同一 recovery プロセス内で minui/DRM が2回目の初期化を行うことがある。DRM backend を実際に終了する場合は、CRTC、connector、plane、property、blob を解放し、blank／バッファー状態をリセットする。そうしないと次の atomic commit が失敗する可能性がある。GUI2 の起動段階で追加の画面復帰同期を呼び出してはならない。

### 画面機能とクイックメニュー

- スクリーンショット、画面消灯、画面復帰、画面録画は、`gui2/backend` の画面 backend を通じてのみ実行する。ページから minui、sysfs、スクリプト、設定ファイルに直接アクセスしてはならない。
- 画面消灯の前に、まず Shell がロック画面オーバーレイを描画し、その後 screen backend が blank を実行する。画面復帰後もオーバーレイはタッチ入力を受け取り続け、スライダーが100%まで完全に到達した場合にのみロック画面を非表示にしてページ操作を再開する。ロック画面には `ic_lock`、半透明背景、ローカライズされたスライド案内を使用し、視覚パラメーターは `ui_metrics` に統一して組み込む。
- 画面録画のデフォルトかつ現時点で唯一の実装は GUI2 の VP8/WebM backend とする。MediaCodec、Stagefright、Codec2、Binder メディアサービス、`screenrecord` を導入してはならない。VP8 エンコードには manifest 管理下の `external/libvpx` を再利用し、WebM の多重化には `external/libwebm` の `libwebm_mkvmuxer` を再利用する。GUI2 内にサードパーティーのソースコードを複製してはならない。
- GUI2 が使用する libvpx API は VP8 encoder API のみ、libwebm は3ファイルの muxer モジュールのみとする。録画機能の導入を理由に VP9、デコーダー、音声トラック、完全なメディアフレームワークを追加してはならない。2つの external プロジェクトの LICENSE/PATENTS/NOTICE ライセンスファイルを維持する。
- RGBX→I420 変換には GUI2 独自の `backend/rgb_to_i420` を使用する。現在の LVGL XRGB8888 はリトルエンディアンのメモリ上では `[B,G,R,X]` であるため、`[R,G,B,X]` として誤って扱わないこと。I420 の U/V プレーンは 2x2 の色差平均を使用し、stride、奇数の幅／高さ、端のピクセル複製を処理する。
- 録画フレームは、このフレームの LVGL flush がすべて完了し、`gr_flip()` が完了した後に送信する。GUI2 は `flush_cb()` によって差分更新される、DRM のダブルバッファーから独立した完全なシャドウフレームを保持すること。direct-scanout 上の scanout/released buffer は、一部の damage 同期しか完了していない可能性があるため、直接読み取ってはならない。ページに LVGL の dirty region がない場合でも、録画フレームレートに従って現在のシャドウフレームを継続的にサンプリングする。画面に変化があった瞬間だけを録画してはならない。I420 変換、VP8 エンコード、WebM 書き込みは、有界のバックグラウンドキューで実行し、LVGL 描画スレッドやタッチスレッドをブロックしてはならない。キューが満杯の場合はフレームをドロップする。
- VP8/WebM 出力は標準 VP8 ビデオトラックと、ファイルモードで後から情報を書き戻せる WebM を使用する。変更後は少なくとも ffprobe、ffmpeg、VLC、または同等の標準プレーヤーで、黒くないテスト画像、タイムライン、フレーム数、サイズを検証する。
- 録画タイムラインには単調増加時計と固定フレームレートを使用する。キューが満杯の場合は元フレームを破棄するが、送信フレームの単調時刻は保持する。停止時には WebM SegmentInfo に実際の録画時間を書き戻す。「エンコードに成功したフレーム数」を録画時間として直接使用してはならない。VP8 では MJPEG のように圧縮パケットを複製してフレームを補完することはできない。
- すべてのバックグラウンドスレッドは終了前に停止し、`join` してリソースを回収する。録画停止、画面消灯、ページ終了、recovery 終了のすべてで WebM の後処理を完了する。
- クイックメニューは shell の永続レイヤーであり、ページ側で作成してはならない。パネル、ボタン、オーバーレイはスクロール不可とし、角丸とシャドウのための安全な余白を確保する。プルダウン時に移動するのはメニューのみで、ステータスバーや下部ナビゲーションは移動させない。
- クイックメニューのプルダウン／上スワイプでは、パネル位置とオーバーレイの透明度を指の動きに追従させる。指を離した後は短いアニメーションで展開または収納を完了する。閾値に達した瞬間に表示／非表示を切り替える方式にしてはならない。スクリーンショットを撮る場合は、先にメニューを閉じ、現在のページフレームを present してから backend のスクリーンショットを実行する。
- 電源ボタン、音量ダウン、電源ボタンとの組み合わせ操作は、GUI2 入力レイヤーで抽象アクションに変換する。ページから Linux キーを直接読み取ってはならない。電源ボタン単押しは画面のオン／オフを切り替え、電源＋音量ダウンはスクリーンショットを実行する。キーの自動リピートは無視する。
- 電源ボタンの短押しを、長押し timeout の判定だけに依存させてはならない。押下と解放が同じ入力ポーリング内で完了する場合がある。画面消灯中も、タッチ入力は画面復帰のために入力レイヤーで消費する必要があるが、指を離すまで LVGL には `RELEASED` として通知する。これにより、画面復帰操作と同時にページ上のコントロールがクリックされることを防ぐ。
- スクリーンショット成功後は shell レベルで短時間の白画面フィードバックを表示する。LVGL の現在のフレームを破壊したり、ページオブジェクトにシステム通知の役割を負わせたりしてはならない。クイックメニューの画面消灯操作は、同じタッチイベントの解放によって画面が直ちに復帰することを避けるため、タッチフレームの送信後まで遅延させる。
- スクリーンショットの通知は、低い不透明度で短時間、柔らかく点滅させる。長時間の全画面純白オーバーレイは使用しない。眩しさやユーザーの視認性低下を避けるためである。
- クイック操作ボタン内のアイコンとテキストは、複数行テキストを含む実際の高さを先にコンテンツグループとして計算し、その後ボタン内部で水平方向・垂直方向ともに中央揃えする。一貫した内側余白を確保し、アイコンとテキストをボタンの上端・下端に別々に固定してはならない。
- ストレージパス、ファイル権限、スクリーンショット形式は旧 GUI の仕様を再利用する。ストレージが利用できない場合は `/tmp/` を使用する。新しい永続設定の書き込みも、必ず backend 経由で DataManager に対して行う。
